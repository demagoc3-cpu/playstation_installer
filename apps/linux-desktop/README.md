# PackageFlow для Linux

Linux-версия настольного PackageFlow, аналог Windows-приложения 1.10.27.
Её задача — держать WEB PackageFlow запущенным как службу. В состав входят:

- **служба** `packageflow.service` (systemd, уровень пользователя): запускает
  встроенный Node.js 22 с WEB. Работает без окна и после закрытия интерфейса;
- **значок в трее** (StatusNotifierItem): открыть окно, запустить или
  остановить службу, автозапуск, настройки, журнал;
- **окно приложения** на WebKitGTK с интерфейсом WEB. Закрытие окна сворачивает
  приложение в трей, служба продолжает работать;
- **проверенный комплект для приставок**, тот же, что в Windows 1.10.27:
  - служба PS5 0.1.29-dev (сборка 029c);
  - приложение PS5 01.000.044 (6c32b25);
  - служба PS4 2.14.

Есть две сборки: `.deb` для Ubuntu и Debian и `.AppImage` для остальных
дистрибутивов. Внутри одно и то же.

## Установка

### .deb (Ubuntu 22.04+, Debian 12+)

```bash
sudo apt install ./packageflow_1.10.27-1_amd64.deb
```

Затем запустите «PackageFlow» из меню приложений.

### .AppImage

```bash
chmod +x PackageFlow-1.10.27-x86_64.AppImage
./PackageFlow-1.10.27-x86_64.AppImage
```

Для работы нужны:
- **python3** — есть в любом настольном дистрибутиве;
- **python3-gi** с GTK 3 — для окна и трея;
- **FUSE 3** — для запуска AppImage. Если его нет, запускайте с
  `--appimage-extract-and-run`.

Файл AppImage держите в постоянном месте, например `~/Applications`: служба
и автозапуск запускают именно этот файл. Если AppImage перемещён, запустите
его один раз из нового места — пути обновятся сами.

### Первый запуск

1. Создаётся и включается `~/.config/systemd/user/packageflow.service`
   (`systemctl --user enable --now`).
2. Создаётся автозапуск значка в трее при входе в систему
   (`~/.config/autostart/packageflow.desktop`).
3. Открывается окно. WEB доступен в сети на порту 3000, как в Windows.

В GNOME значок в трее показывает расширение AppIndicator. В Ubuntu оно
включено по умолчанию; в других дистрибутивах установите
`gnome-shell-extension-appindicator`. KDE, XFCE и Cinnamon показывают значок
сами.

## Меню значка

- **Открыть PackageFlow / Открыть в браузере.**
- **Состояние службы:** работает, запускается, остановлена или ошибка. Если
  установлена новая версия, а служба ещё старая, появляется подсказка
  перезапустить службу.
- **Запустить / Остановить / Перезапустить службу.** Перед остановкой
  приложение спрашивает у WEB (`/api/desktop/prepare-stop`), нет ли активных
  заданий. Если задания есть, остановка выполняется только после отдельного
  подтверждения.
- **Запускать при входе в систему** — включает или выключает сразу и службу,
  и значок в трее.
- **Настройки:**
  - порт WEB (по умолчанию 3000);
  - порт передачи на приставку (по умолчанию 3001);
  - IP компьютера в сети;
  - каталог данных.
- **Журнал службы** — `journalctl --user -u packageflow.service`.
- **Проверить обновления / Установить обновление X.** Обновления берутся из
  GitHub Releases `demagoc3-cpu/playstation_installer` по тем же правилам, что
  в Windows:
  - только стабильные выпуски;
  - у файла должен быть SHA-256 от GitHub;
  - ссылка строго из этого репозитория;
  - при загрузке проверяются размер и хеш.

  Для `.deb` ищется `packageflow_<версия>-<ревизия>_amd64.deb` и
  устанавливается через `pkexec apt-get install` (запросит пароль). Без
  `pkexec` пакет открывается в установщике системы.

  Для AppImage ищется `PackageFlow-<версия>-x86_64.AppImage`; файл заменяется
  на месте.

  Перед установкой служба останавливается, только если нет активных заданий.
  Задания не прерываются: при активных заданиях обновление откладывается. После
  установки служба и значок запускаются уже новой версией.

  Через 20 секунд после запуска выполняется одна тихая проверка. Устанавливается
  обновление только по нажатию.
- **Поддержать проект…** — кошельки проекта, те же, что в Windows
  (`Assets/donations.json` из закреплённого коммита). Для каждого есть кнопка
  «Копировать адрес» и QR-код.
- **Закрыть окно и значок** — служба продолжает работать.
- **Выйти и остановить службу** — полный выход. Служба останавливается с той же
  проверкой активных заданий, затем закрываются окно и значок. При следующем
  входе в систему всё запустится снова, если включено «Запускать при входе».

## Настройка поиска (как в Windows)

Пункт трея **«Настроить поиск…»** открывает мастер, который сам устанавливает и
настраивает всё для поиска и загрузки игр.

1. **qBittorrent-nox 5.2.4** — загрузка торрентов. Отдельный профиль, только
   `127.0.0.1`, случайный пароль (PBKDF2-SHA512, как в Windows). Подключается к
   WEB через `/api/torrents/settings`, папка загрузок выбирается в мастере.
   Официальный AppImage qBittorrent — это программа с окном, а для службы нужен
   вариант без окна, поэтому используется статическая сборка тех же исходников
   из `userdocs/qbittorrent-nox-static` (на неё ссылается вики qBittorrent).
   Если `qbittorrent-nox` уже установлен в системе, используется он.
2. **FlareSolverr 3.5.2** со стабильным **Chrome for Testing** — официальной
   сборкой Google для автоматизации. Канал Stable, размер и MD5 сверяются по
   Google Storage, сборка ставится в `components/chrome-for-testing`.
   Скрытый браузер работает на Xvfb. Если Xvfb нет, мастер сам ставит `xvfb` с
   запросом пароля администратора.
   - **Почему не встроенный Chromium.** С этого IP страницы входа и поиска
     RuTracker закрыты управляемой проверкой Cloudflare. Встроенный в выпуск
     FlareSolverr Chromium 153.0.8010.0 (промежуточная сборка) её не проходит;
     стабильный Chrome 155 и Chromium 152 из Docker-образа FlareSolverr
     проходят («Challenge solved!», около 11 с).
   - **`LANG=C.UTF-8`, как в Docker-образе.** FlareSolverr передаёт `LANG`
     браузеру как `--accept-lang`, и с `en_US.UTF-8` проверка Cloudflare
     проваливалась.
   - **Исправление для новых систем.** FlareSolverr (сборка PyInstaller)
     передаёт Chromium `LD_LIBRARY_PATH` на свои старые библиотеки X11. На
     Ubuntu 26.04 / glibc 2.43 из-за этого падает процесс отрисовки
     («Unable to receive message from renderer»). Мастер ставит вместо
     `_internal/chrome/chrome` небольшую обёртку, которая возвращает Chromium
     системные библиотеки и запускает Chrome for Testing.
3. **Prowlarr** (официальная сборка `linux-core-x64`) — только `127.0.0.1:9696`,
   свой API-ключ. Если на этом компьютере уже работает свой Prowlarr (например,
   в контейнере), мастер подключается к нему по API-ключу и ничего не
   переустанавливает. То же со сторонним FlareSolverr на порту 8191.
4. **Прокси «PackageFlow FlareSolverr»** с тегом `packageflow-rutracker`. Если
   Cloudflare блокирует проверочный сайт Prowlarr, прокси сохраняется только
   после того, как RuTracker действительно открылся через FlareSolverr.
5. **RuTracker.org** — индексатор по логину и паролю, сначала проверка, потом
   сохранение. Если RuTracker просит код с картинки, кнопка «Войти вручную»
   открывает окно браузера для одного входа, после чего настройка повторяется.
6. **Поиск в WEB** — `/api/search/settings` (Torznab, категория 1180) и
   проверочный запрос.

Компоненты загружаются из официальных выпусков на GitHub с проверкой размера и
SHA-256, распаковываются в `~/.local/share/PackageFlow/components` и работают
как службы `packageflow-qbittorrent`, `packageflow-flaresolverr` и
`packageflow-prowlarr`. Они запускаются и останавливаются вместе с
`packageflow.service`.

Секреты лежат в `~/.config/PackageFlow/search.json` с правами 600: пароль
qBittorrent, ключ Prowlarr, логин и пароль RuTracker. Пароль RuTracker хранится
также в базе Prowlarr.

Повторный запуск мастера ничего не переустанавливает: он проверяет готовность
компонентов и меняет только то, что нужно, например логин RuTracker.

## Команды

```bash
packageflow                    # окно и значок в трее
packageflow --tray             # только значок (так запускает автозапуск)
packageflow --status           # состояние службы и WEB в JSON
packageflow --start
packageflow --stop             # откажет при активных заданиях; --force — всё равно
packageflow --install-service  # сервер без графики: включить и запустить службу
packageflow --remove-service   # выключить службу и автозапуск
packageflow --check-update     # есть ли новая версия (JSON)
packageflow --update           # загрузить, проверить и установить (без прерывания заданий)
packageflow --version
```

Для AppImage вместо `packageflow` используйте путь к файлу `.AppImage`.

Чтобы служба работала, даже когда никто не вошёл в систему (сервер в шкафу):

```bash
loginctl enable-linger $USER
```

## Где лежат данные

| Что | Путь |
|---|---|
| Настройки | `~/.config/PackageFlow/settings.json` |
| Ключ запускателя (права 600) | `~/.config/PackageFlow/launcher.key` |
| Данные WEB (библиотека, приставки, очереди, ключи сопряжения) | `~/.local/share/PackageFlow/web` |
| Сведения о запущенной службе | `~/.local/state/PackageFlow/server.json` |
| Файлы службы для AppImage (около 170 МБ, одна версия) | `~/.local/share/PackageFlow/runtime/<версия>` |

Служба из AppImage работает не из смонтированного образа, а из своей копии
файлов. Поэтому закрытие процессов AppImage и замена файла при обновлении не
останавливают WEB. Копия создаётся при первом запуске новой сборки, прежняя
удаляется.

При запуске служба заново проверяет комплект для приставок (имена, размеры,
SHA-256) и копирует его в `<данные>/console-setup` и
`<данные>/ps5-service-updates`, как Windows `ConsoleArtifacts.Stage`.
Изменённый комплект не принимается.

## Обновление и удаление

- **.deb:** `sudo apt install ./новая-версия.deb`, затем «Перезапустить
  службу» в меню значка.
- **AppImage:** замените файл и перезапустите службу.
- **Удаление:** `sudo apt remove packageflow` или удаление файла AppImage.
  Данные и настройки при этом сохраняются. Чтобы выключить службу и
  автозапуск, перед удалением выполните `packageflow --remove-service`.

## Сеть

Приставки скачивают пакеты с компьютера, поэтому WEB слушает `0.0.0.0` на
портах 3000 и 3001, как в Windows. Если включён брандмауэр:

```bash
sudo ufw allow 3000:3001/tcp
```

## Чего пока нет по сравнению с Windows

- Нет управления qBittorrent, Prowlarr и FlareSolverr: Windows-запускатель
  скачивает их Windows-сборки. Внешний qBittorrent можно указать в
  настройках WEB.
- Нет окна входа на RuTracker и мастера первичной настройки приставок
  запускателя. Настройка приставок доступна в самом WEB.
- Ключ запускателя хранится в файле с правами 600, а не в DPAPI. Служба
  должна читать его без открытой сессии.
- Переноса данных из Windows нет: каталог `.data` можно скопировать вручную в
  `~/.local/share/PackageFlow/web` при остановленной службе.

## Сборка

Нужны Node.js 22 и npm (или `PF_NPM_CLI`), python3-gi, `dpkg-deb` и
`mksquashfs`.

```bash
python3 scripts/build.py              # оба пакета
python3 scripts/build.py deb          # только .deb
python3 -m unittest -v tests/test_core.py
```

Что берёт сборка (закреплено в `pins.json`):

- **WEB** — коммит 873ab80, тот же, что в Windows 1.10.27. Собирается через
  `git archive` в `build/web`; рабочая копия WEB и её `.nuxt` не
  затрагиваются.
- **Комплект для приставок** — из выпуска Windows 1.10.27. Проверяются хеш
  `manifest.json` и все файлы.
- **Node.js 22.23.3 linux-x64** — с nodejs.org, проверяется по
  SHASUMS256.
- **Среда AppImage type2** — закрепляется по SHA-256 при первой загрузке.

Результат: `dist/packageflow_<версия>-1_amd64.deb`,
`dist/PackageFlow-<версия>-x86_64.AppImage` и `dist/SHA256SUMS`.
