# Управление PS4 — PKG 1.19 / API 0.6.0

## Что добавлено

| Раздел WEB | Возможность |
| --- | --- |
| На консоли | Название и версия игры из установленного SFO/PKG, обложка с консоли; при необходимости сведения из библиотеки ПК |
| На консоли → выбранная игра | Состояние приложения, запуск и остановка именно этой игры |
| Библиотека → базовый PKG | Переустановка с проверкой удаления и последующей установки |
| О системе | Проверка GitHub, выбор PKG на ПК, установка обновления и отдельная команда перезапуска |

Если обложки нет, остаётся значок с буквой. Если названия нет ни на консоли, ни в библиотеке, остаётся TITLE_ID. SLUS/SLES и другие пользовательские TITLE_ID поддерживаются наряду с CUSA; системные приложения и сервис защищены от обычного удаления и управления.

## Первое обновление

1. Дождаться завершения установки/удаления. Установить `PackegeFlowService-1.19.pkg` поверх 1.18 вручную на PS4.
2. Открыть запускатель один раз, дождаться HTTP READY и штатного закрытия. В WEB «О системе» должны отображаться API 0.6.0 / PKG 1.19.
3. Обновить и перезапустить WEB. Сохранённое сопряжение используется автоматически; вводить код снова не требуется, если каталоги данных сохранены.
4. В «На консоли» проверить заголовки, версии и обложки. Открыть отдельную тестовую игру, нажать «Запустить» и проверить состояние на PS4. Затем «Остановить» и подтвердить остановку. Несохранённый игровой прогресс при остановке может потеряться.
5. Проверить, что демон продолжает отвечать после запуска игры.

Готовый PKG: 6 619 136 байт. SHA-256:

```text
2cedb42c91038730b1145e907cb56906e7d683b50a744744c8b0dc6c5e58aeaf
```

## Переустановка игры

Переустановка целиком удаляет прежнюю базовую игру, обнаруженные патчи/бэкпорты и DLC. Пользовательские сохранения остаются. После удаления устанавливается **только выбранный базовый PKG**; патчи и DLC нужно поставить заново. Это видно в подтверждении перед командой.

Для проверки выбрать небольшую тестовую игру с доступным исходным PKG. Остановить её в «На консоли», найти базовый PKG в библиотеке и нажать «Переустановить». Проверить состав и ввести TITLE_ID. WEB начинает установку только после подтверждённого полного удаления. Частичный сбой останавливает этот переход.

Закрытие страницы не отправляет команду повторно. При возвращении WEB продолжает наблюдение сохранённого задания. Для перехода от удаления к установке должна работать проверка состояния WEB: если страницы закрыты, открыть библиотеку снова. Если результат неизвестен, проверить состояние на консоли; автоматической повторной команды нет.

PyLoader остаётся способом установки по умолчанию, включая обычные патчи, DLC и торренты. Переустановка через сервис — отдельная операция. Перезапись установленной игры без удаления её дополнений не заявляется.

## Может ли сервис обновить и перезапустить себя?

Реализована схема **демон → новый PKG запускателя → новый запускатель → замена демона**:

1. WEB проверяет собственный TITLE_ID, CONTENT_ID, категорию, версию и SHA-256 PKG.
2. Демон системно удаляет только старый запускатель PFLS00001 и устанавливает новый через BGFT. Отдельный PFLS00002 продолжает работать.
3. После подтверждения установки WEB предлагает «Перезапустить сервис». Сначала нужно закрыть активную игру.
4. Демон запускает новый PFLS00001. Запускатель останавливает прежний собственный демон и устанавливает новый тем же способом, который уже работает в проекте.
5. WEB считает обновление завершённым только после ответа `/system/info` с ожидаемой новой версией.

Сопряжение хранится отдельно от PKG и сохраняется. Первую 1.19 ставим вручную: в предыдущей версии нет нового API обновления. Полный цикл обновления из WEB можно проверить следующей более новой сборкой; загрузка той же или старой версии блокируется.

Если установка нового запускателя не завершилась, работающий демон остаётся доступен, но запускатель может потребоваться установить вручную. Если новый запускатель не открылся автоматически, открыть его на PS4 вручную. При обрыве связи повторная установка сама не отправляется.

Проверка GitHub выполняется при открытии раздела с известной текущей версией и по кнопке. Она предлагает обновление, а установка требует подтверждения. Используется [страница релизов проекта](https://github.com/demagoc3-cpu/playstation_installer/releases); на 29.09.2026 опубликованных релизов нет. Пока можно выбрать проверяемый PKG на компьютере. Публикация релиза — отдельный следующий шаг.

## API и восстановление

Новые методы демона требуют прежний Bearer ключ сопряжения; браузеру ключ не передаётся.

| Демон, порт 12801 | Назначение |
| --- | --- |
| `GET /apps/icon/{TITLE_ID}` | Ограниченная PNG-обложка из фиксированных путей/PKG |
| `GET /apps/runtime/{TITLE_ID}` | Наличие приложения в Lnc, его AppId |
| `POST /apps/control` | UUID, TITLE_ID, действие `launch`/`stop`; для остановки ожидаемый AppId |
| `GET /apps/control/{requestId}` | Сохранённый результат команды управления |
| `POST /install/service-update` | Установка исключительно собственного PFLS00001 |
| `POST /apps/control`, действие `restart` | Запуск собственного обновлённого запускателя после проверки подтверждённого update requestId |

WEB использует `/api/ps4/apps/{icon,runtime,control}`, `/api/ps4/reinstall`, `/api/ps4/maintenance` и `/api/ps4/service-update/*`. Все изменяющие маршруты проверяют Origin и формат запроса. Перед единственным POST намерение сохраняется на диск. После потери ответа выполняется чтение прежнего задания; при неизвестном результате новая команда блокируется.

Данные WEB: `.data/console-control.json`, `.data/console-maintenance.json`, `.data/service-updates/`. Журнал управления PS4: `/data/PackegeFlowService/control-v1.bin`. История ограничена 128 командами управления на PS4; переполнение блокирует новые команды. Удаления и установки продолжают использовать собственные существующие журналы.

## Что проверено

- 32 теста WEB: порядок удаления/установки, частичный сбой, изменение состава, потеря ответа, восстановление, защита от повторов, обновление и подтверждение новой версии.
- Реальные PS4-объекты управления и установщика с имитацией системных вызовов: AppId, выбранное приложение, защищённые TITLE_ID, однократный запуск, scoped обновление собственного PKG и отложенный перезапуск.
- Чтение состава и обложок: appmeta, SFO внутри PKG, отсутствие метаданных, границы файлов и 64-битные размеры.
- Nuxt production build и упаковка PKG: SFO, SELF, стандартный `libkernel`, штатный create-fself, импорты и состав пакета.
- Готовый PKG 1.19 через изолированную локальную версию WEB: загрузка, версия и SHA-256, манифест и точные HTTP Range-фрагменты; отображение названия, обложки и кнопок в браузере.

Пользователь подтвердил установку игры, стабильный фон и работу раздела 1.18. **Новые команды 1.19 ещё не испытаны на реальной PS4.** Особенно нужно проверить доступность экспортов Lnc через SystemService на прошивке 12.50 и полный цикл обновления более новой сборкой.

## Первичные источники

Запуск и остановка сверены с [исследованием PS4 daemon и Lnc](https://github.com/LightningMods/PS4-daemon-writeup/blob/main/writeup.md). Сохраняются обычный `libkernel` и штатный create-fself, с которыми наш демон уже запускается.

Последовательность переустановки сопоставлена с [исходником установщика Itemzflow](https://github.com/LightningMods/Itemzflow/blob/main/itemzflow/source/installpkg.cpp): системное удаление перед повторной регистрацией BGFT. Методы удаления компонентов — [Remote PKG Installer](https://github.com/flatz/ps4_remote_pkg_installer/blob/master/installer.c). Дополнительный референс: [STORM PS4 PKG INSTALLER](https://github.com/ReiKatari/STORM_PS4_PKG_INSTALLER).
