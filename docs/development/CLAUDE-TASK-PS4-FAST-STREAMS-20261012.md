# PS4: применить измеренное ускорение в следующем кандидате

12 октября 2026. Нативную службу PS4 исправляет Claude, WEB и аппаратные замеры — Codex. Пользователь передаёт это задание самостоятельно. Не делать push и не отправлять пакет на приставку.

## Измеренная база

Codex проверяет `af2cd91` / кандидат 2.09 на PS4 Pro FW 12.50 (10.1.10.32) с компьютера WEB 10.1.10.47, через службу 12801, без PyLoader. Полный отчёт и таблица повторов: `docs/development/PS4-THROUGHPUT-HARDWARE-20261012.md` в WEB; копия отчёта для тебя будет в PS/tests.

При запросе SO_RCVBUF/SO_SNDBUF 1 или 2 МиБ приставка фактически выделяет **524288 байт**, ошибок SDK нет. Увеличение числа poll до 16 не устраняет ограничение базы. Уменьшение сна до 500 мкс помогает, но увеличение сокетного буфера даёт больший прирост сети. Нет необходимости увеличивать net pool или требовать фактические 2 МиБ. Запись на диск колеблется, поэтому её предел не объявлять равным пределу сети.

## Что реализовать

1. Добавить профиль `sockbuf512k`, который просит **512 КиБ** и всегда читает фактический результат через getsockopt. Нужен отдельный A/B-замер: нельзя считать, что запрос 512 КиБ гарантированно даст тот же результат, что запрос 1 МиБ с ограничением ОС. Сохранить старые профили и явный `baseline` для сравнения.
2. После этого применять измеренную настройку к **сокетам, которыми владеет наша служба**: тесты, отправка файлов и приём PUT. Ошибка setsockopt или getsockopt не должна останавливать старый рабочий путь; сохранить исходную настройку и сообщить о фактическом результате. Ограничить память по числу клиентов, не выделять целый файл, не менять сокетную авторизацию, таймауты, докачку и уборку. Не задавать крупные буферы всем коротким JSON-запросам без необходимости.
3. Подготовить один отдельный комбинированный профиль `sockbuf512k-sleep500` для проверки остаточного ограничения записи. В нём менять только два уже измеренных параметра. Сохранить 16 мс сна в простое, ограниченный бюджет обработки, обслуживание info/status и отсутствие busy-spin. По результатам Codex решит, нужен ли более частый цикл по умолчанию.
4. Сохранить ring 8 × 1 МиБ по умолчанию; **не применять ring2m/ring4m** как доказанное ускорение. Во втором аппаратном повторе оба дали около 5 МиБ/с, writeMs 47–51 секунд на 256 МиБ, при стабильной скорости теста сети. Первый повтор был около 41 МиБ/с. Однако затем **baseline с блоком 1 МиБ тоже упал до 4,43 МиБ/с**, writeMs 55,54 секунды, а sleep500 — до 10,02 МиБ/с. Поэтому виновность размера кольца НЕ доказана; последние дисковые замеры нельзя использовать как чистое A/B-сравнение. Codex остановил свой следующий тест записи и завершил сетевые повторы отдельно. Нужна диагностика накопленной/фоновой нагрузки, свободного места, времени отдельных write, количества медленных write и ожидания писателя, без чтения пользовательских файлов. Разделить размер блока кольца и размер одного write(): текущий writer передаёт write() весь блок 1/2/4 МиБ. Подготовить отдельный профиль с кольцом прежнего размера и write порциями ≤256 КиБ; отдельно исследовать крупное кольцо с такими же малыми порциями. Не объявлять это доказанным ограничением диска. Память кольца ≤16 МиБ, fsync/проверка размера/удаление обязательны.
5. Обратно проверить 409 при активном benchmark, включая PUT и локальные маршруты, отмену, разрыв, восстановление и пустой каталог после теста. Не менять ключ, автоматическое подключение, FW-проверки, изоляцию очередей, Sony-вызовы установки и удаление игр.
6. **Не обещать ускорения PKG через BGFT.** BGFT скачивает URL самостоятельно, его сокет не является сокетом нашей службы. Настройки net pool/benchmark не доказывают влияние на BGFT. Сохранить timing задания; Codex отдельно сравнит реальную длительную установку и HTTP-источник WEB. PyLoader тоже отдельный путь. Параллельная установка на несколько PS4 остаётся только через службу, по одному заданию на приставку.

## Диагностика и проверки

Не терять диагностику v1, фактический сон, буфер, ringFull и ошибки SDK. В аппаратной серии был один 409 между завершёнными тестами: причину нельзя объявлять найденной без воспроизведения. Следующий кандидат должен различать в диагностике console busy (install/apps/files/update) и собственный benchmark busy, без выдачи ключей и без изменения успешного договора. Любой 409 не должен создавать второй поток; после освобождения консоли доступен новый тест.

Host-тесты: профили, фактическое ограничение буфера ОС, отказ/нечитаемый getsockopt, откат, временный файл, медленный диск, отмена, таймаут и 409 до мутаций; прежние install/files/UI тесты. Сборка BENCHMARK_READY=1, NET_POOL_KB=256, номер **2.10 только в копии сборки**, прежние Title/Content ID и название PackageFlow. Отчёт со SHA256 и ограничениями в `CLAUDE-REPORT-PS4-FAST-STREAMS-20261012.md`. Аппаратный PASS отмечает только Codex после замеров.
