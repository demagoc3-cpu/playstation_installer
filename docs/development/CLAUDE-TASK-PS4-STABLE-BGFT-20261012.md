# Claude: стабилизировать PS4 после экспериментов 2.13

Решение пользователя: оставить установку через BGFT. Собственный установщик без BGFT отложен. Убрать лишние экспериментальные режимы и их тесты, сохранив штатный пользовательский тест скорости и проверки надёжности. Изменения только в службе/приложении PS4; WEB, самостоятельный ELF PS5 и PyLoader не менять. Код сторонних установщиков не переносить.

Это задание заменяет дальнейшие A/B-этапы FILE-PIPELINE. Исторические отчёты и сырые результаты не удалять. Самостоятельные исследования heap8МиБ, прямого PKG URL вместо манифеста, собственного установщика и оверлея в этот кандидат не включать.

## Основание

Аппаратный отчёт Codex: `CODEX-REPORT-PS4-213-FILE-PIPELINE-20261012.md`; данные: `evidence/ps4-213-file-pipeline-hardware-20261012.json`.

- PUT32МиБ по4МиБ в порядке sync/async/async/sync:64.79/57.04/62.05/74.99МиБ/с. В native диагностике подтверждены соответствующие писатели, все SHA256 совпали. Async преимущества в этой серии не показал, оставлять его в штатном кандидате незачем.
- Сеть WEB→PS4:111.31/111.41МиБ/с; сеть+запись:87.94/96.39МиБ/с. Это пользовательский benchmark службы, не скорость BGFT.
- short: задержка info около2мс вместо17мс baseline. Сохранить рабочий алгоритм short.
- На2.12 альтернативный StartTask(service) не сократил задержку до первого байта:32.54/32.60с. Сохранить прежний IntDownloadStartTask.
- Колебания скорости BGFT30–70МиБ/с остаются; ни socket512КиБ нашей службы, ни short не объявлять их исправлением. Новый алгоритм Sony не добавлять.

## Оставить в штатном варианте

1. BGFT: прежняя регистрация и `sceBgftServiceIntDownloadStartTask`. Опции, entitlement, PlayGo, типы базы/патча/DLC, системные права и опросы не менять. Подтверждать установленную игру реальным состоянием, а не окончанием выдачи HTTP или наличием записи до завершения. Не создавать повторную установку по таймауту.
2. Обычный синхронный PUT, с подтверждением offset только после успешного write/fsync. Разрыв, finish/abort, точный offset, повтор блока, пути, revision/identity и авторизация должны сохранить прежнюю семантику.
3. Рабочий short:1мс при открытом клиенте/активности последних250мс,16мс в настоящем простое, без busy-spin. Сохранить ограниченный бюджет обработки и отзывчивость status/cancel.
4. Буферы собственных крупных файловых сокетов512КиБ с откатом при отказе ОС; net pool256КиБ. Чтение максимум4МиБ, общий бюджет ответов8МиБ,503 при нехватке бюджета. PUT максимум4МиБ. Эти размеры не превращать в публичные A/B-настройки.
5. Пользовательскую модалку скорости в WEB поддерживать без изменения договора: `/benchmark/info`, upload/download/disk, latency через info, Bearer, отказ при Origin, request-id, ready/busy, maxBytes, modes. Сохранить требуемые полные bytes/complete/cleanup/elapsedMs, writeMs/syncMs/receivePipeline там, где они уже предусмотрены. Дисковый тест по-прежнему ограничен памятью, приём и запись параллельны, fsync обязателен, только собственный временный файл с уборкой. Это отдельный писатель benchmark; его не удалять вместе с экспериментальным PUT-писателем.
6. Busy в обе стороны, причины отказа409, защита временных файлов от ссылок, уборка после перезапуска. Автоматическое сопряжение, ключ и разрыв сопряжения неизменны.
7. Обычный прогресс установки и скорость BGFT сохранить. Не удалять всё поле timing только ради уборки: оставить полезные итоговые длительности принятия/начала/скачивания/подтверждения, от которых зависят штатные клиенты. Секундные A/B-массивы и подробные экспериментальные трассы можно убрать, проверив потребителей.

## Удалить лишнее

- Экспериментальный async PUT: реализацию, переключатель putWriter, настройки/флаг сборки, неиспользуемые исходники и специфичные для этой удалённой реализации тестовые цели.
- Переключатель bgftStart int/service и альтернативный вызов StartTask. Удалить только действительно неиспользуемый импорт альтернативного вызова; используемые Stop/GetProgress и другие вызовы Sony сохранить.
- Runtime-переключатель loopWait и экспериментальный baseline, если не нужны штатному коду. Рабочий short оставить обычным алгоритмом, с прежним16мс в настоящем простое.
- Публичные A/B-профили sleep500/polls16/sockbuf*/ring*/write256k и их подбор. Оставить один проверенный профиль теста скорости. Проверить совместимость старого заголовка default/baseline: либо безопасно принимать как штатный режим, либо явно отказать400; не включать скрыто другую настройку. WEB без заголовка должен продолжить работать.
- `/benchmark/settings`: после удаления всех экспериментов убрать маршрут или вернуть явный410 без изменения настроек. Не оставлять успешный фиктивный ответ о включении удалённых режимов.
- Подробные кольцевые журналы requests/fileTransfers, экспериментальные счётчики и тесты матрицы удалённых профилей. Минимальные результаты пользовательского benchmark и полезные ошибки сохранить. Не ломать bounded JSON и не добавлять частый production-лог каждого чанка.
- Неиспользуемые NET_POOL_KB/LOOP_WAIT_DEFAULT/PUT_WRITER_DEFAULT настройки A/B из штатной сборки, если они больше не требуются; BENCHMARK_READY не считать экспериментальным подбором скорости. Сохранить честную квалификацию пользовательского теста.

## Проверки и кандидат

- Удалять тесты только для удалённых экспериментальных веток. Сохранить/адаптировать проверки штатной установки, файлов, offset, durable commit, разрыва/докачки, abort, ошибок fsync, авторизации/отзыва ключа, busy, memory budget, полного SHA256 и уборки.
- Проверить настоящий HTTP-сервер: обычный PUT8×4МиБ и хвост, восстановление после разрыва; два чтения4МиБ и третий503; status при крупном чтении; все три пользовательских benchmark, второй тест409, временный файл удалён. Не вводить новые серии аппаратного подбора.
- Прогнать относящиеся к сохранённой функциональности host-тесты и сборку. Если прежний test-self-update ещё падает из-за фикстуры обновления до1.93 при текущей2.03, исправить только версию фикстуры на выше текущей и проверить сохранённую семантику self-update. Не скрывать FAIL удалением проверки и не менять механизм обновления ради теста.
- Собрать кандидат2.14 с BENCHMARK_READY=1 после регрессий; номер только в копии сборки по принятой схеме. НазваниеPackageFlow, Title IDPFLS00001/PFLS00002 и Content ID сохранить. Без вшитого WEB/адресов стенда/ключей.
- Отчёт: что удалено, что сохранено, совместимость API, результаты тестов, коммит, размер и SHA256 пакета. Отдельно отметить всё непроверенное на аппаратуре.

Не передавать на приставки и не делать push. После отчёта Codex проверит совместимость с WEB и кандидат на PS4. Итог этой задачи — один стабильный путь BGFT и файловый API без экспериментальной матрицы, с работающим пользовательским тестом скорости.
