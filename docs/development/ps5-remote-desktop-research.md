# Удалённое управление меню PS5: исследование 2026-10-10

Запрос пользователя: изображение системного меню PS5 и управление настройками
через PackageFlow и наш фоновый ELF. Игровой стриминг не является целью.
Стенд — PS5 Slim 13.60; сейчас недоступен. Статус: research, no console transfer.
Производственный код, SDK, сборки, настройки приставки и capabilities не менялись.

## Вывод

Remote Play уже предоставляет изображение консоли и кнопки контроллера, включая
PS для открытия центра управления. Поэтому интеграция Remote Play — наиболее
обоснованный путь к первому работающему удалённому интерфейсу. Sony описывает
включение отдельно для каждого пользователя и сопряжение устройства в локальной
сети. Это подтверждает возможности штатного сервиса, но не нашу интеграцию на
13.60. Источники: [управление Remote Play](https://www.playstation.com/en-us/support/games/playstation-remote-play-on-mobile-devices/?country-selector=true),
[настройки и сопряжение](https://www.playstation.com/en-gb/support/games/remote-play-settings/).

Полностью собственный путь «ELF → изображение в WEB → нажатия в системное меню»
имеет конкретные зацепки, но ещё не доказан. Нужно проверить два независимых
механизма: доступ к пикселям системного композитора и ввод, который принимает
ShellUI. Доступ к кадру собственного приложения и чтение собственного геймпада
не подтверждают эти механизмы. Работоспособность на PS5 13.60 не объявляем.

## Вариант A: наш ELF помогает встроенному Remote Play

Предлагаемая схема:

```text
WEB → авторизованный сеанс PackageFlow → ELF: диагностика / сопряжение
WEB ← видеомост на ПК ← штатный Remote Play PS5
WEB → кнопки → видеомост на ПК → штатный Remote Play PS5
```

Клиент вроде Chiaki-NG уже решает транспорт видео и контроллера. Интеграция
в браузер всё равно потребует локального helper/моста: HTTP-прокси PackageFlow
сам по себе не реализует протокол Remote Play. Видеоформат для WEB, перекодирование
и WebRTC либо иной транспорт — отдельные проектные решения, пока не реализованные.

Что полезно из ps5upload:

- `payload/src/remoteplay.c`: загрузка библиотеки, получение PIN, проверка
  пользователя и разрешений, аккуратное разделение статуса и ошибок.
- `payload/include/rp_keys.h`: структура настроек. Отсутствие разрешения для
  пользователя может мешать соединению даже после успешного сопряжения.
- `engine/crates/ps5upload-core/src/rp_session.rs` прямо сообщает, что видео не
  построено. Управляющий сеанс входа не заменяет полный Remote Play.

Важная граница: upstream `rp_cb_prepare` вызывает `rp_ensure_enabled`, поэтому
«получить PIN» в этой реализации может изменить настройку. LinkDev тоже пишет
registry. Нельзя копировать эти операции в диагностику и называть её read-only.
Наша первая диагностика должна только сообщать состояние и требуемые действия.
Не менять account ID, не выполнять fake sign-in/активацию автоматически и не
предлагать обновление прошивки как часть исследования. Сохранение пользователя
и совместимости его сохранений важнее автоматического обхода prerequisites.

## Вариант B: захват и виртуальный контроллер внутри нашего ELF

### Изображение

Прочитаны `src/SharpProspero/Platform/SystemAvCapture.cs` и
`src/SharpProspero/Interop/AvCapture/Avcap2.cs` по закреплённой версии.
Обёртка открывает `/system/common/lib/libSceAvcap2.sprx`, разрешает
`sceAvcap2Initialize`, `OpenVideo`, `Start`, `ReadVideo`, `GetFramePitch`,
`Stop`, `Close`, `Terminate`. Upstream помечает доступ как привилегированный.

Конфигурация имеет размер 0x2B8, дескриптор кадра — 0x68. В его начале находятся
нерасшифрованные `Word0`…`Word10`; код проверяет result/status. Там нет готового
читателя плоскостей, доказанной геометрии и pixel format. `IsValid` не доказывает,
что адреса доступны нашему процессу. Нужны происхождение ABI, mapping/direct
memory, размеры/stride/цветовой формат и подтверждение ShellUI в фоне. Даже
доступность библиотеки на 13.60 ещё не проверена нашим стендом.

У `ShareCapture.cs` другой интерфейс: запрос асинхронного снимка с записью в
галерею. Это возможный исследовательский резерв, но не готовый поток и не
доказанный захват экрана «Настроек» из фонового ELF. Не создавать постоянный
поток через галерею до оценки задержек, файлов и прав.

В нашем SDK v0.43 есть импорты VideoOut, но они в основном обслуживают вывод
буферов приложения. Наличие функции регистрации/блокировки буфера не означает
доступа к готовому системному кадру. Отдельные Avcap2-стабы среди просмотренных
библиотек не найдены; это не доказательство отсутствия модуля в прошивке.

### Нажатия

В локальном `libScePad.so` присутствуют экспорты
`scePadVirtualDeviceAddDevice`, `DeleteDevice`, `InsertData`,
`scePadRemoteControlInsertData`, `scePadSetProcessPrivilege`. Это SDK-стабы,
не реализация Sony и не аппаратное подтверждение полномочий нашего ELF.
Прототипы, структуры отчётов и привязка к пользователю требуют проверки.

[Документ Control4Free](https://github.com/MoHadiShibli/Control4Free/blob/252e26d2b7a4e5d48dcfa4101191c9dd63f27b2e/docs/how-it-works.md)
показывает на PS4 необходимость Mbus, прав процесса, отдельного виртуального
устройства и корректной последовательности отчётов. Его GoldHEN, контейнер
процесса, форматы данных и способы поиска device ID нельзя считать ABI PS5.
Создавать следует только собственное устройство и удалять только его.

## Сравнение

| Путь | Сильная сторона | Неподтверждённое для нашего решения |
|---|---|---|
| Remote Play + helper | Существующий PS5-клиент, готовые видео и кнопки | Наши prerequisites на 13.60, видеомост в браузер, lifecycle/auth |
| ELF + Avcap2 + virtual pad | Соответствует запросу собственного фонового сервиса | Реальные пиксели ShellUI, ABI/права, глобальный ввод, работа в фоне |
| ShareCapture + кнопки | Может дать редкие снимки | Меню в фоне, задержка, запись в галерею, очистка, права |
| API отдельных настроек | Удобно для конкретных операций | Полного удалённого рабочего стола не даёт |

Рекомендация: независимо исследовать прямой ELF-путь и держать Remote Play
практическим резервом. Не начинать с патчей ShellUI или произвольных kernel offsets.

## Предлагаемый MVP и аппаратная проверка после возвращения PS5

Цель интерфейса — экран консоли, D-pad, крест/круг, Options и PS. Мышь браузера
сначала нажимает экранные кнопки; произвольный клик по пикселю PS5 не равен
поддержке мыши в ShellUI. Для собственного захвата можно целиться в 720p,
5–10 обновлений/с без звука. Это продуктовая цель, не измеренная возможность
Avcap2 и не подтверждённый профиль Remote Play. Для Remote Play сначала
использовать поддержанный клиентом профиль; снижение отображаемой частоты
на WEB не гарантирует уменьшения исходного трафика.

1. Дождаться доступной и здоровой сессии PS5. Не повторять старые подвисшие
   Sony-пробы; исследование не разрешает автоматический перезапуск приставки.
2. Проверить точные пути/экспорты и ABI. Наличие файла/символа даёт только
   availability. Загрузка/инициализация модуля уже создаёт состояние, поэтому
   не выдавать её за чистую read-only проверку. Не вызывать функции с угаданной
   сигнатурой.
3. Отдельный ограниченный helper захвата: пользователь вручную открывает
   «Настройки» и меняет выделение. Получить действительно декодируемый кадр,
   показать изменение и доказать, что это ShellUI, а не поверхность нашего UI.
   Пока это не удалось, управления не добавлять.
4. Отдельный input helper: создать собственное устройство; один безопасный
   D-pad импульс в меню, затем нейтральный отчёт. Проверить PS/круг, возврат
   физического управления и удаление своего устройства. Не подтверждать
   опасные системные диалоги во время проверки.
5. Проверить потерю соединения: короткая аренда управления, watchdog,
   отпускание всех кнопок, запрет воспроизведения старых отчётов. Удалять
   только собственные ресурсы. Не завершать чужую Remote Play-сессию.
6. Только затем объединять с WEB и измерять FPS, задержку, CPU/RAM и влияние
   на установку. Порядок cleanup и общий лимит времени каждого helper заранее
   описать; не обещать, что таймаут исправит зависший системный вызов.

Просмотр и управление требуют существующего сопряжения PackageFlow; один
владелец управления на приставку, короткоживущие сеансы и явное отключение.
Ключи Remote Play хранить в серверном helper, не выдавать браузеру. После
перезапуска собственный ELF не работает до его повторной загрузки; управление
загрузочным экраном через него пока обещать нельзя.
