# Windows: первоначальная настройка PS4 и PS5

Статус: кандидат следующего выпуска, не опубликован. Нативные приложения
собирает Claude по `CLAUDE-TASK-PS-APPS-021.md`; Windows, WEB и ELF — Codex.
Аппаратный запуск нового комплекта на PS5 проверяется отдельно от Windows UI.

## Поведение мастера

Окно «Приставки» объединяет сохранённые профили и найденные устройства.
Есть добавление IPv4 вручную, выбор платформы, проверка службы, сопряжение
по коду и выбор конкретного адресата. Выбор хранит consoleId, платформу и IP;
смена активной приставки не переносит ключ другой приставки.

Поиск использует read-only Sony DDP (PS4 UDP 987, PS5 UDP 9302) и ограниченные
проверки HTTP в ближайшей /24. TCP 9021 проверяется только для уже известной
PS5. Компьютер с открытым портом не считается приставкой. DDP system-version
не выдаётся за прошивку; WebKit и kstuff пока показываются «Не проверено».
Отключённые профили не показывают сохранённую прошивку как свежую проверку.

PS4 сохраняет существующий путь через GoldHEN/PyLoader и PKG. PS5 требует
выполненного эксплойта, загрузчика ELF на 9021 и прошивки 13.60. Для первого
запуска пользователь указывает прошивку из системных настроек; это ввод
пользователя, а не автоматическое доказательство совместимости.

PS5: установить ELF → дождаться подтверждения точной версии/buildId/PID →
ввести код сопряжения → запустить ShadowMount+ → установить приложение.
Мастер не загружает эксплойт и не запускает kstuff или ShadowMount+ сам.
Используется имя PackageFlow и постоянный PPSA95001. Формат приложения
принимается только при подтверждённой поддержке работающей службы.

## Комплект в Windows payload

В `payload/console-setup/` должны быть `manifest.json`, ELF и один образ
приложения. Отсутствующий комплект не мешает PS4, но блокирует PS5-установку
с понятным сообщением. Не использовать старые numbered кандидаты или
случайные файлы `dist` как артефакты релиза.

Пример структуры манифеста (значения SHA256 и размера заполняет сборка):

```json
{
  "schemaVersion": 1,
  "elf": {
    "fileName": "PackageFlowService-PS5.elf",
    "size": 4059944,
    "sha256": "<64 lowercase hex characters>",
    "version": "0.1.15-dev",
    "buildId": "ps5-service-management-015h",
    "firmware": "13.60"
  },
  "app": {
    "fileName": "PackageFlow.ffpkg",
    "size": 5447680,
    "sha256": "<64 lowercase hex characters>",
    "name": "PackageFlow",
    "titleId": "PPSA95001",
    "contentId": "IV0000-PPSA95001_00-PACKAGEFLOWUI001",
    "version": "01.000.041",
    "format": "ufs2"
  }
}
```

Размеры выше — примеры, не контрольные значения артефактов. Указывать реальный
формат образа (`ufs2`, `exfat`, `pfs`, `ffpfsc`), который проверит парсер PARAM.
Сборка проверяет контрольные суммы обоих файлов и заголовок ELF. WEB дополнительно
читает PARAM образа и сверяет имя, Title ID, Content ID, версию и платформу.

Linux: `PF_PS5_BUNDLE=/path/to/verified-bundle bash packaging/windows/build.sh ...`.
Windows: `./packaging/windows/build.ps1 -Ps5Bundle C:\path\verified-bundle ...`.
Скрипт упаковки не скачивает приватный ELF и не включает токен приставки.

При запуске мастер копирует проверенный комплект в папку данных WEB; этот же
каталог данных используется режимом Compose. Манифест публикуется последним.
WEB-контейнеру не требуются доступ к приватному репозиторию и ключ GitHub.

## Защита от повторов

Маршруты `GET/POST /api/desktop/console-setup` требуют закрытый launcher key;
POST также проверяет Content-Type, Origin и состояние остановки WEB.
Перед отправкой ELF сохраняется durable intent. Если связь оборвалась после
отправки, повторный GET только сверяет состояние; второй ELF не отправляется.
Существующая служба другой версии направляет пользователя к обычному обновлению.
Неподтверждённые установка/обновление/отправка ELF блокируют конкурирующую операцию.

Установка приложения использует сохранённый requestId, привязанный к consoleId
и SHA256 приложения. Квитанция записывается до постановки в очередь. После
перезапуска повтор команды возвращает прежнюю квитанцию, а не новую установку.
«Установлено» показывается по подтверждённому результату очереди PS5.

Опрос статуса использует уже проверенный комплект, пока размер, inode,
mtime/ctime файлов не изменились. Перед отправкой и установкой SHA256
проверяется полностью независимо от кэша статуса.

## Совместимость нативного каталога

`catalog/v1` остаётся PS4 по умолчанию; явный `platform=all|ps4|ps5` расширяет
просмотр. Capability `catalogFeatures` подтверждает фильтр платформы, подробности
игры и метаданные отдельных пакетов. Нативный клиент не предполагает их наличие
в старом WEB. Установочные API продолжают проверять платформу адресата.
В каталоге нет локальных путей и bearer-ключей.

## Проверки

- Core: разбор DDP, точные признаки PS5, неизвестная прошивка, manifest/hash,
  сохранение адресата. Windows SDK build — отдельная проверка компиляции.
- WEB: PARAM и SHA256, изменение кэшированного файла, журнал после перезапуска,
  отправка ELF ровно один раз при потере ответа, несовпадение прошивки/версии.
- Настоящий Nuxt на синтетических приставках: legacy v1, фильтр PS4/PS5,
  метаданные, launcher authorization, отсутствие комплекта, Origin, очереди.
- Windows 11: интерактивный WinForms-тест нового окна и прежних страниц;
  его данные временные, автоматическая установка служб отключена preview-режимом.
- PS5: полный свежий комплект ещё требует аппаратной проверки. Предыдущие
  успешные тесты отдельных форматов не подменяют проверку нового мастера.

Открытая задача: первый адрес WEB для приложения PS4 до сопряжения. Старый
путь мастера сохранён; Claude должен убрать зависимость нативного клиента
от адреса конкретного стенда и описать способ настройки при недоступном WEB.
