# PackageFlow: первая установка, повторная установка и обновления PS5

Дата: 2026-10-11. Это план развития с отдельными отметками выполненного. Непроверенные шаги не являются возможностями опубликованного релиза.

## Что работает сейчас

- Windows-мастер содержит проверенный комплект ELF 015h и приложения PackageFlow 01.000.041, PPSA95001. Первая передача, сопряжение и регистрация проверены на PS5 Slim 13.60.
- ELF — отдельный фоновый процесс. Нативное приложение — интерфейс, его закрытие не останавливает ELF.
- В WEB уже есть механизм обновления ELF через `/api/consoles/service-update`: подготовка, остановка собственной нагрузки, одна передача и подтверждение нового процесса. Источник — подготовленный проверенный артефакт на WEB.
- Windows использует `/api/desktop/console-setup` для первоначального запуска ELF и установки приложения. Он пока не является полноценным интерфейсом обновления всех компонентов.
- Исправлен повтор установки после удаления приложения: прежняя квитанция не считается доказательством наличия. Сначала проверяется завершение точной попытки, затем фактическое состояние PS5. Новое задание допускается только после ответа «отсутствует». Если старая попытка неизвестна, связь потеряна или версия отличается, автоматическая переустановка не начинается. Эти изменения проверены локально; полный сценарий удаления/повторной установки ещё требует испытания на PS5.
- Подготовлен кандидат ELF 015i с системным именем процесса `PackageFlow.elf`; полные host-тесты и сборка SDK прошли, отображение в Payload Manager требует проверки на PS5. Текущая нагрузка на снимке пользователя — `payload.elf`, PID 110. PID не является постоянным идентификатором.
- Иконка PackageFlow добавлена в настройки сборки NSIS для установщика и удаления, а также в запись Windows «Установленные приложения». В собранном установщике проверены ресурсы иконок: все 7 размеров совпадают с исходным ICO.

## Подготовка PS5

Для проверенного маршрута на 13.60 нужны выполненный совместимый эксплойт, kstuff, загрузчик ELF на порту 9021 и ShadowMount+ для образа приложения. Мастер не выполняет эксплойт и не устанавливает эти зависимости автоматически.

После загрузки нашего ELF он должен оставаться запущенным для работы WEB. Для управления из WEB открывать нативное приложение постоянно не нужно. FTP, CheatRunner и ps5upload не являются обязательными компонентами нашего HTTP-маршрута. Payload Manager удобен для запуска и автозагрузки; при другом совместимом загрузчике сам менеджер не обязателен.

После перезагрузки нужно снова выполнить предусмотренный эксплойтом запуск нагрузок. Автозагрузка — отдельная проверка, наличие приложения в библиотеке не доказывает запуск ELF. Удаление записи в менеджере не равно остановке процесса. Удаление карточки приложения не всегда удаляет исходный образ, который ShadowMount+ может зарегистрировать снова.

## Повторная установка из Windows

1. Установить актуальный Windows-комплект поверх прежнего. Сопряжение, библиотека и настройки сохраняются.
2. Открыть «2. Приставки → Найти / подключить», выбрать конкретную PS5, нажать «Проверить».
3. Если ELF отсутствует: подготовить PS5, закрыть игру, ввести прошивку 13.60 и нажать «Установить». Отправка выполняется один раз, затем мастер сверяет ответ нагрузки.
4. Сохранённое сопряжение использовать повторно. Для действительно нового сопряжения ввести код уведомления PS5 и нажать «Сопрячь».
5. Нажать «Установить» для приложения. При наличии прежнего результата мастер сверяет состояние с PS5; установленное приложение не передаёт повторно.

Отдельный случай для следующей реализации: данные сопряжения на PS5 сохранились, приложение удалено, а ключ на Windows утрачен. Нужен локальный способ получить новый код без установленного приложения и без чтения секретного файла через FTP. Сейчас обновление кода реализовано через локальный интерфейс приложения; нельзя обещать полностью автоматическое восстановление такого состояния.

## Общая схема обновления WEB и Windows — к реализации

Оба интерфейса должны работать с одним серверным координатором и одними журналами конкретной приставки. Операции: «Установить/обновить нагрузку», «Установить/обновить приложение», «Обновить оба». Нельзя создавать независимые очереди из разных интерфейсов.

### Версии и источники

- Единый манифест содержит версию ELF, build ID, SHA256, размер, поддержанные прошивки и протоколы; для приложения — постоянный Title ID, Content ID, версию PARAM, формат, SHA256 и требования к ELF.
- Сверять ELF с живым авторизованным ответом `/api/v1/status`, приложение — с каталогом и сведениями PS5. Локальные отметки WEB и старые квитанции недостаточны.
- Различать «уже актуально», «доступно обновление», «отсутствует», «несовместимо» и «не удалось проверить». Не менять неизвестное состояние на «установлено».
- Поддерживать проверенный комплект Windows и подготовленный комплект WEB. Общий валидатор должен исключить ситуацию, когда мастер умеет установить ELF, но WEB не видит его как кандидат обновления.
- Закрытый репозиторий ELF не требует пользовательского GitHub-токена в установщике. Распространять одобренные бинарники через комплект/канал обновлений, с проверкой манифеста и файлов. Не публиковать приватные исходники ради обновления.
- Не предлагать понижение версии автоматически. Одинаковая версия с другим build ID/hash должна быть явно обозначена как отдельная сборка.

### Нагрузка

1. Получить свежие состояние очереди, активное приложение, прошивку и готовность загрузчика.
2. Если идут установка, восстановление сохранений или другие мутации — объяснить причину ожидания, сохранить отзывчивый интерфейс.
3. Если открыта игра/приложение — показать точное название и предложить закрытие. Не закрывать чужую игру молча.
4. Через существующий механизм подготовки остановить именно наш ELF. Сохранить сопряжение и данные. Не останавливать kstuff, ShadowMount+ или загрузчик.
5. Перед отправкой сохранить намерение, затем отправить один ELF. При потере ответа не повторять отправку; сверять живую версию/build ID и устойчивый журнал.
6. Подтвердить новую нагрузку авторизованным ответом, обновить сведения в обоих интерфейсах.

Откат ELF после неизвестного результата не выполнять автоматически: второй слушатель опасен. Сначала доказать состояние первой передачи. Возможность отката показывать только при подтверждённой остановке и доступном совместимом предыдущем артефакте.

### Приложение

1. Сохранить постоянные имя `PackageFlow` и Title ID PPSA95001; не создавать новые диагностические карточки для обычных обновлений.
2. Прочитать версию с PS5, проверить требования формата и ELF, показать текущую и целевую версии.
3. Убедиться, что приложение закрыто; не заменять смонтированный образ работающего приложения.
4. Сохранить команду обновления, передать образ с докачкой, проверить SHA256, заменить источник и регистрацию через проверенный маршрут образов.
5. Подтвердить Title ID, Content ID, версию и фактическую регистрацию. Сохранения и пользовательские игры не затрагивать.
6. Сбой после замены источника должен иметь явное состояние восстановления; старую карточку/образ сохранять до точки, в которой новый результат подтверждён. Нельзя обещать откат, пока этот переход не реализован и не проверен.

Для «обновить оба» порядок задаёт совместимость манифеста: обычно сначала совместимый ELF, затем приложение. Если новую нагрузку старая версия приложения не поддерживает, необходимо заранее описанное окно совместимости или последовательность, проверенная для обеих версий.

## Windows-интерфейс — следующий этап

- В таблице приставок отдельно показать текущие версии нагрузки и приложения, доступные версии и состояние проверки.
- Кнопка «Обновить PackageFlow» открывает окно с выбором компонентов и причинами недоступности; первая установка и восстановление доступны там же.
- Ход операции: подготовка, передача с МБ/скоростью, проверка, регистрация/перезапуск, подтверждение. Поиск и наблюдение можно остановить без повторной отправки принятой команды.
- Повторное открытие окна продолжает наблюдение за прежним журналом. При потере ответа текст должен отличать «операция не выполнена» от «результат пока неизвестен».
- Обновление самой Windows-программы остаётся отдельным: NSIS безопасно останавливает собственный WEB, заменяет файлы и сохраняет пользовательские данные.

## Установка и удаление из Windows — 11 октября 2026

Реализовано в WEB и Windows-мастере; ELF и нативное приложение не менялись.

- Ручной выбор платформы удалён из окна поиска/добавления. Для IP выполняется ограниченная проверка PS4/PS5-служб, затем Sony DDP; подтверждённый ответ ELF определяет PS5. Порт 9021 сам по себе ничего не доказывает. Текущий ELF остаётся PS5-only, прошивка 13.60; PS4 использует существующий PyLoader/службу.
- «Установить» сохраняет продолжение для выбранной PS5. После подтверждённого запуска ELF пользователь вводит код; «Сопрячь» автоматически продолжает проверку/установку приложения. Сопряжение с другой приставкой не запускает чужое продолжение.
- Первый запрос установки, как и повтор старого запроса, проверяет наличие приложения на самой PS5. Точное совпадение версии/Content ID пропускает передачу. Недоступность и другая версия не допускают слепую установку поверх.
- «Удалить приложение» привязано к PPSA95001 и Content ID комплектного PackageFlow. Читаются управляемый источник, его identity и активное приложение. Выполняется существующая команда `delete`, удаляющая источник вместе с регистрацией; не `uninstall`, которая сохраняет образ. Идентификатор команды хранится в Windows, повтор читает журнал.
- Удаление только карточки в меню PS5 не означает удаление исходного образа ShadowMount+. В этом случае сканирование может вернуть карточку. Перехват удаления через меню Sony не реализован; мастер предоставляет правильный маршрут удаления источника. Старые тестовые Title ID автоматически не удаляются.
- «Удалить устройство» удаляет профиль и ключ этого Windows/WEB, работает без сети, блокируется при незавершённых заданиях/восстановлении. Ключи других приставок и данные консоли сохраняются. Это локальное отключение клиента, не отзыв общего токена на PS5. Полный отзыв уже есть в нативном приложении: «Подключения → Разорвать сопряжение». Для нового подключения после удаления Windows-профиля получить новый код на приставке.
