## Как делает ps5upload

[inspect.rs](https://github.com/phantomptr/ps5upload/blob/096afd94365e1b61dd13dc510579e062fd6af99f/engine/crates/ps5upload-engine/src/inspect.rs):

- PS4: минимум из целочисленного `SYSTEM_VER` в PARAM.SFO; SDK из `PUBTOOLINFO.sdk_ver`.
- PS5: заявленный минимум из `requiredSystemSoftwareVersion` в param.json; SDK из `sdkVersion`.
- Значения прошивок декодируются из упакованных BCD/hex-представлений. Title ID сам по себе не кодирует требуемую прошивку.

[fpkg_firmware.rs](https://github.com/phantomptr/ps5upload/blob/096afd94365e1b61dd13dc510579e062fd6af99f/engine/crates/ps5upload-engine/src/fpkg_firmware.rs): отдельная проверка для конвертируемых PS5-игр. Читает SDK-пары eboot.bin и каждого sce_module/*.prx, принимает только известные пары, берёт максимальную. Сниженный минимум возвращает только если все модули удалось распознать и результат ниже заявленного значения PARAM. Непрочитанный модуль не позволяет понизить требование. Этот анализ нуждается в самих файлах; метаданных torrent для него недостаточно. Не считать его гарантией запуска на любой конфигурации.

[titleDetails.ts](https://github.com/phantomptr/ps5upload/blob/096afd94365e1b61dd13dc510579e062fd6af99f/client/src/lib/titleDetails.ts) и `collection/online.rs` используют ORBISPatches/PROSPEROPatches по CUSA/PPSA для названия и обложки. В проверенном коде эти функции не извлекают прошивку из базы.

## Другие первичные источники

- [n1ghty/pkg_tools](https://github.com/n1ghty/pkg_tools): читает SYSTEM_VER из PARAM.SFO, показывает SYS_VER и SDK_VER отдельно.
- [PS4 PKGVault](https://github.com/rcinformatique/ps4-pkgvault): также использует SYSTEM_VER из PARAM.SFO.
- [ORBISPatches: пример CUSA44977](https://orbispatches.com/CUSA44977): минимум прошивки указан отдельно для каждой версии официального патча.
- [PROSPEROPatches: пример PPSA01372](https://prosperopatches.com/PPSA01372): разные версии патчей одной игры требуют разных прошивок. Для поиска нужна пара Title ID + точная версия пакета; Content ID уточняет конкретное издание, если доступен.
- [Check-Game-Firmware](https://github.com/OfficialAhmed/Check-Game-Firmware) определяет требования сравнением дат выпуска игры и прошивки; автор прямо отмечает неточность. Не использовать такую оценку как достоверный тег совместимости.

## Рекомендуемая логика для WEB

1. В поиске использовать явно обозначенные требования и бэкпорт из названия/описания раздачи, включая структурированные поля страницы. Фоновое получение описания обновляет тег без задержки основной выдачи.
2. Хранить отдельно заявленный минимум оригинала, цели бэкпорта, верхнюю границу, региональные варианты, источник и исходную строку. Значения `4.xx` не превращать в точное `4.00`; дефисы в перечислениях не превращать автоматически в непрерывный диапазон. Сохранять ограничения вроде «до 13.60».
3. Если сведений раздачи нет, запросить базу по точному Title ID и версии. Показать «Оригинал FW … / ORBISPatches» или «Оригинал FW … / PROSPEROPatches». При неизвестной версии, несовпадении издания или отсутствии записи оставить прошивку неизвестной; не подставлять требования последнего патча.
4. База официальных патчей не подтверждает прошивку изменённого бэкпорта. Её значение не должно перекрывать явно указанные цели бэкпорта или превращать такую карточку в «точно совместимо».
5. После скачивания показывать отдельные требования из конкретного PARAM и SDK. Исследование SDK всех модулей PS5 — отдельная будущая задача, а не часть быстрого torrent-поиска.
6. Примеры тегов: `FW 9.00` с источником «автор раздачи»; `Backport 5.05 / 6.72 / 7.02`; `FW 4.xx–13.60` при такой явно указанной границе; `Оригинал FW 11.02` с базой и версией патча. Номер APP_VER без явного FW-контекста не считать версией прошивки.

Внешние запросы следует выполнять на WEB, с ограниченным параллелизмом, таймаутом и кешем по платформе, Title ID и версии. Сбой базы не должен мешать поиску и загрузке раздачи. Цвет тега отражает источник/тип сведений; зелёное подтверждение реального запуска по одному числу прошивки не давать.
