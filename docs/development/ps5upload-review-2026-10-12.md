## Что означает цитата пользователя

Сборщик образов теперь принимает папку на PS5 (`ps5://`) или сохранённом
сервере (`remote://`). Прежде эти источники принимал только сборщик PKG.
`engine/.../fpkg_api.rs:808` проверяет удалённый источник и открывает его через
общий `ps5upload_fpkg::source::open`. Файлы читаются по мере сборки, без
предварительной полной выгрузки исходной папки на компьютер.

Готовый образ записывается в output directory движка: `.partial`, проверка,
публикация. Последующая отправка на PS5 — отдельный этап. Это не подтверждение
запуска игры непосредственно с NAS и не сетевой блочный механизм PS5.

Convert организован в четыре шага: игра, результат, применимые параметры,
сборка/установка. Он рекомендует маршрут по типу игры и прошивке, скрывает
Kraken/язык для образов, показывает filesystem/FFPFSC/LZ4/read-back для образов.

Ограничение выше 11.60 у upstream относится к PS5 fake game PKG, а не ко всем
PKG и не к минимальной требуемой прошивке из PARAM. В комментариях
`client/src/lib/ps5Firmware.ts:44` отдельно исключены PS4 и homebrew, но текущая
эвристика `isPs5GameId` распознаёт PPSA. Наше homebrew имеет PPSA95001:
переносить эту эвристику без исключения собственного приложения нельзя.

## Почему PackageFlow требует ×2

1. `server/utils/device-installation.ts:119` и `:181`: WEB без разбора формата
   удваивает сумму выбранных/ожидающих байтов для PS5. Комментарий говорит про
   staged PKG, но формула применяется также к Folder и образам.
2. `PackageFlowPayload-PS5/src/core/folder.c:123`: создаётся приватная
   `/data/packageflow-ps5/<id>.folder-stage`.
3. `folder.c:131` вызывает `copy_verified`: уже принятые
   `/data/packageflow-ps5/transfers/<entry-id>.pkg` полностью читаются,
   хешируются и копируются в дерево игры.
4. `folder.c:145` переименовывает готовое дерево в `/data/homebrew/<title>`.
   Это переименование само по себе не создаёт третьей полной копии.
5. Файлы передачи после публикации не удаляются этим маршрутом. Таким образом,
   в пике есть исходники передачи + почти полная готовая папка; после успеха
   остаются игра + исходники передачи. После ошибки может остаться частичная
   folder-stage. `pf_transfer_cancel` отказывает complete=true с 409 и не
   очищает завершённые файлы.

Это реальная потребность текущего алгоритма, а не только неточный текст WEB.
Для 100 ГБ Folder получается около 200 ГБ данных плюс накладные расходы.
Размер удалённого пользователем каталога сам по себе не позволяет установить
его прежний состав: после удаления точный список и размеры уже не проверить.

Для образов также есть вторая копия: `src/core/image.c:300` копирует
проверенный transfer в приватный файл в homebrew и затем публикует его.
Поэтому пока нельзя просто заменить коэффициент в WEB на единицу.

## Как делает PS5Upload

[payload/ava1/ava1_apply.c](https://github.com/phantomptr/ps5upload/blob/b18c7de5a685eed0272d128e7bb7638a35181dc5/payload/ava1/ava1_apply.c):

- `ava1_apply_path:77` направляет файлы в дерево назначения/приватный stage.
- `commit_large:2821` проверяет корневой хеш, синхронизирует принятый файл,
  при необходимости переименовывает его на месте. Проверки не отменены.
- `ava1_apply_commit_ready:2961` ставит завершение файлов в рабочую очередь.
- `finish:2998` завершает фоновые операции, проверяет конфликт и один диск,
  затем `rename(j->base,j->root)` публикует готовое дерево. Полная папка не
  копируется второй раз. Журналы и временные упаковки небольших файлов тоже
  занимают место; утверждать нулевые накладные расходы нельзя.

[space.rs](https://github.com/phantomptr/ps5upload/blob/b18c7de5a685eed0272d128e7bb7638a35181dc5/engine/crates/ps5upload-ava1/src/space.rs)
и [send.rs](https://github.com/phantomptr/ps5upload/blob/b18c7de5a685eed0272d128e7bb7638a35181dc5/engine/crates/ava1/src/send.rs):
нужно разместить unfinished_bytes минус подтверждённые PS5 held_bytes.
Свободное место читается для конкретного диска назначения; учитывается
небольшой резерв и обещанный объём других операций на том же диске.
Дополнительный расход внутреннего хранилища upstream оценивает примерно
в пятую часть и показывает как предупреждение, не как универсальный ×2.
Это их наблюдение, не независимо проверенная нами константа для всех PS5.

[ava1_journal.c](https://github.com/phantomptr/ps5upload/blob/b18c7de5a685eed0272d128e7bb7638a35181dc5/payload/ava1/ava1_journal.c):502
очищает просроченные журналы/принадлежащие заданиям незаконченные staged
деревья с проверкой возраста, часов и владения. Не удаляет все данные службы.
В 7.0.10 интерфейс согласовал срок докачки семь дней с приставкой.

## Полезные следующие изменения PackageFlow

Приоритет 1 — убрать вторую полную копию Folder/образа, сохраняя проверки и
восстановление после сбоя. Целевая схема: заранее проверенный манифест,
приём в принадлежащее заданию приватное дерево на диске назначения, хеширование
и синхронизация, адресная публикация переименованием. Подтверждать одинаковый
`st_dev` до rename: upstream описывает kernel panic при междисковом rename
на PS5. Защита от существующего чужого title/источника сохраняется.

Переходные старые transfer-планы требуют отдельной совместимости. Если вместо
прямого приёма перемещать прежние `.pkg` в stage, нужно устойчиво фиксировать
перемещение и научить статус/докачку находить единственную копию после сбоя.
Простая замена `copy_verified` на `rename` ломает прежний transfer receipt.

После этого менять расчёт WEB: оставшиеся байты + резерв + операции на том же
диске; отдельные модели для Folder, образа и PKG. Докачку кредитовать только
по фактическому ответу PS5. Для PKG учитывать размер установленного содержимого
и маршрут установки, не переносить экономию Folder на все PKG.

Приоритет 2 — очистка по заданиям с явным объёмом и сохранением настроек:
отдельные «Остановить и сохранить докачку» и «Удалить временные данные»;
проверка владения каждого файла/stage, защита активных операций, ключей,
настроек, установленных игр и rollback незавершённого восстановления сохранений.
Конфигурацию и кэш следует разделить, чтобы очистка места не отключала функции.

Другие полезные изменения upstream:

- 7.0.13: последовательное крупное чтение exFAT и параллельное хеширование при
  read-back. Их 169 МиБ/с → 3,7 ГиБ/с — замер образа в кэше на компьютере,
  а не скорость сети или PS5.
- 7.0.13: повреждение 7z — постоянная ошибка с именем файла; не бесконечный
  повтор как при сетевом сбое.
- 7.0.10: автозагрузка ELF ждёт после появления загрузчика, чтобы не попасть
  в незавершённую цепочку jailbreak. Готовый порт 9021 не доказывает готовность
  ядра; их задержку 90 секунд нельзя считать универсальным аппаратным тестом.
- 7.0.10: сохранение нагрузки под своим именем в Payload Manager и управление
  порядком автозапуска. Это полезно для понятного PackageFlow.elf.
- 7.0.6: поиск нового IP только для той же идентичности сопряжённой приставки.
- 7.0.13: выбор прямого/посреднического маршрута PS5 → PS5, отдельный dial address.
- 7.0.12: Stored PKG без сжатия как запасной вариант при отказах запуска
  сжатых PKG. Применимо к будущему сборщику, не заменяет наш текущий Folder.
- 7.0.14: единый читатель локальных/PS5/серверных источников и понятный мастер
  конвертации. Следующий этап после исправления передачи/места/очистки.

Необходимые проверки новой схемы: host crash/recovery до/после публикации,
ENOSPC, отмена, конфликт назначения, неизменность чужих файлов, совместимость
старых планов, точный учёт докачки и нескольких заданий; затем собственный
маленький fixture на Slim13.60 с замером фактического расхода. В этой исследовательской
проверке новые ELF/WEB не собирались и аппаратный PASS не заявлен.
