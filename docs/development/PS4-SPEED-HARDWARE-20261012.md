## Первая PS4

Windows `100.86.206.80` → PS4 `192.168.0.113`, FW 12.00. Пользователь подтвердил кабель PS4. Физический Realtek Ethernet Windows: **1 Gbps**. Скорость согласованного линка самой PS4 ещё не прочитана.

Host-тесты actual PS4 benchmark/install прошли. Первые попытки в sandbox не могли отправлять данные даже через AF_UNIX (`EPERM`); повтор вне ограничения прошёл без изменения исходных тестов. Первый HTTP запрос сразу после обновления имел таймаут до начала потока; повтор и последующие квалификационные потоки прошли.

## Вторая PS4

Пользователь добавил `10.1.10.32` в локальный WEB на 0.0.0.0:3000. PyLoader отвечает ready, служба 12801 сначала отказала в соединении. Пользователь самостоятельно обновляет службу до 2.08. После запуска прочитаны реальная версия 2.07, FW 12.50 и модель PS4 Pro. Тест не начался при busy во время этого обновления; повторная установка не отправлялась. Старая локальная отметка PKG 2.04 не используется как доказательство версии устройства. В старой завершённой очереди есть delivered-квитанция прежней установки запускателя; её данные не удаляются автоматически.


Пользователь завершил обновление второй PS4 до 2.08; system/info подтвердил FW 12.50, модель PS4 Pro. Прямой маршрут локального WEB 10.1.10.47 → 10.1.10.32, интерфейс ens18 виртуальный, его скорость линка неизвестна. Старый delivered элемент очереди не переписывался; к началу замера пользовательская очередь уже имела статус cancelled, обслуживание failed (прежняя отменённая переустановка). Стандартный WEB admission разрешил тест только после отсутствия активной операции.

Disk write 1933,8 мс, fsync 12,8 мс; pipeline/cleanup true. Ready true после теста, четыре результата сохранены. Артефакты `/tmp/pf-ps4-local-208-web-results.json`, `/tmp/pf-ps4-local-208-web-check.log`, визуальное подтверждение `/tmp/pf-ps4-local-208-speed-window.png`.

Сходная скорость на двух приставках и разных источниках усиливает гипотезу общего ограничения сетевого пути службы, но не доказывает конкретный виновный параметр. Idle latency около 17 мс согласуется с 16 мс сна в коде вне теста; внутри потока сон 2 мс. Изменение этого параметра должен проверять Claude отдельным A/B кандидатом вместе с реальными socket buffers/net pool. Совместная установка двух игр на двух приставках аппаратно не проверялась этой работой; изоляция двух сервисных workers проверена интеграционными тестами WEB.
