## Правки WEB

- Чтение файлов из проводника и копирования договаривается о maxReadBytes по /files/capabilities: до4МиБ, старая служба256КиБ. Кэш5секунд, раздельно поIP/ключу, до64 записей. Более крупная логическая порция на старой службе разбивается на прежние256КиБ.
- Повтор только отклонённого чтения503, до3попыток с100/250мс; тот же offset. Запись и установки этим повтором не затронуты. Ответы ограничены запрошенным объёмом; EOF остаётся видимым вызывающей стороне.
- delivery.startup сохраняет первые времена манифеста/данных/первого блока поIP/пакету/попытке; capturedFromStart=false отмечает подключение измерения к уже идущей старой попытке. Reset новой установки удаляет прежние времена. Значения Date.now захватываются перед чтением метаданных, длительности — performance.now.
- Первые события пишутся однократно: Range-запросы больше не заполняют журнал сотнями одинаковых записей. Буфер отдачиPKG1МиБ из575c393 сохранён.

Работающий локальный WEB подтвердил capability200, maxReadBytes/maxUploadBytes4194304, readBudgetBytes8388608; третья реальная установка подтвердила startup.capturedFromStart=true и4начальных события вместо сотен. Windows установленный WEB в этой работе не обновлялся.

## Реальный файловый API

Свой32МиБ случайный файл, UUID-каталог /data/packageflow-speed-…; PUT8×4МиБ, finish, чтение256КиБ /4МиБ /4МиБ /256КиБ. Без активной пользовательской очереди; перед каждой порцией проверялось отсутствие нового задания. Полный объём иSHA256 каждой серии совпали. Свой файл и пустая папка удалены сrevision/identity; cleanup=true.

Максимальная задержкаinfo25.73мс. Два одновременных чтения по4МиБ прошли и совпали с источником; аппаратная проверка третьего клиента503 и отзыва пользовательского ключа не проводилась.

Поля диагностики не включают время до инициализации transfer в main.c.
