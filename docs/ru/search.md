## Поиск через Torznab (Jackett / Prowlarr)

Раздел **«Поиск»** в боковом меню работает с любым Torznab‑совместимым API.

1. Установите [Jackett](https://github.com/Jackett/Jackett) или [Prowlarr](https://github.com/Prowlarr/Prowlarr) и добавьте в него трекеры, которыми вы имеете право пользоваться.
2. Скопируйте **Torznab URL** индексатора и **API‑ключ**:
   - Jackett: `http://127.0.0.1:9117/api/v2.0/indexers/<indexer>/results/torznab/`
   - Prowlarr: `http://127.0.0.1:9696/<id>/api`
3. В PackageFlow: **Источник** → название, URL, API‑ключ и категории → **Сохранить**. По умолчанию указана категория `1180` (PS4). Другие категории вводятся через запятую; пустое поле означает поиск по всем платформам. При изменении настроек пустое поле API‑ключа сохраняет прежний ключ.
4. Введите запрос → **Найти** → откройте карточку → **Скачать** или **Скачать и установить**. Загрузкой занимается qBittorrent; второй вариант включает автоустановку PKG через службу PS4.

По умолчанию результаты сортируются по новинкам. WEB запрашивает страницы по 50 записей; **«Показать ещё»** загружает следующую страницу без повторов. Сортировка действует на все уже загруженные результаты. Если источник передаёт общее количество, оно отображается рядом с количеством загруженных карточек.

Число результатов зависит от индексатора. Некоторые адаптеры возвращают только первую страницу самого трекера: например, проверенный адаптер RuTracker в Prowlarr не запрашивает следующие страницы трекера. Увеличение `limit` на стороне PackageFlow это не исправляет. При пустом или повторном ответе кнопка загрузки следующей страницы исчезает.

Первый запрос к трекеру может выполняться дольше повторного: WEB ожидает ответ до 60 секунд. Ошибки API‑ключа или ответа Torznab показываются как ошибка поиска, а не как отсутствие результатов.

## Карточки результатов

Результаты отображаются карточками. Выберите карточку, чтобы увидеть размер, сиды и личеры, дату, источник и полное название раздачи. Метки версии, языков и Backport берутся из названия; это сведения автора, а не результат проверки PKG.

Для видимых карточек приложение заранее загружает описание и обложку со страницы раздачи, если источник передал ссылку. Одновременно выполняется не больше двух запросов; карточка при открытии использует уже начатый запрос или готовые данные. Если страница требует входа или недоступна, сведения из Torznab остаются доступны. Фоновая загрузка и наведение на карточки используют только HTTP. При открытии карточки RuTracker может вызвать локальный FlareSolverr, если HTTP-запрос заблокирован; адрес можно задать переменной `PACKAGEFLOW_FLARESOLVERR_URL` (по умолчанию `http://127.0.0.1:8191`).

«Скачать» передаёт раздачу qBittorrent. «Скачать и установить» дополнительно включает существующую автоустановку PKG через PackageFlowService после загрузки. Открытие карточки не запускает скачивание.

## Кеш описаний

Успешно загруженные описания, сведения автора и ссылки на обложки сохраняются в `.data/search-details-cache/` на 24 часа и переживают перезапуск WEB. Неудачные ответы не сохраняются. Кеш автоматически очищается; хранится около 1000 записей. Сиды, личеры и другие данные раздачи обновляются через Torznab при новом поиске.

Это HTTP-запросы страниц, без загрузки torrent-файлов. Cookies успешно проверенной страницы и User-Agent используются для следующих HTTP-запросов к тому же источнику и хранятся только в памяти WEB до 15 минут. Cookies не передаются другим сайтам и не записываются в кеш описаний. Когда HTTP принимает проверку, Chromium закрывается сразу. Если источник всё ещё требует браузер, сессия используется с последовательными запросами и закрывается после пяти минут простоя. Первый запрос к новой странице может занять больше времени, чем открытие уже загруженной карточки.
