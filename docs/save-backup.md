# Сохранения PS4: экспорт и восстановление

Область функции: **только сохранения игр**. Файлы PKG, игры, патчи и DLC в резервную копию не входят.

## Как это устроено в других приложениях

- Apollo Save Tool экспортирует сохранение в расшифрованном виде, в том числе в структуру `/PS4/APOLLO/<user>_<title>_<save>/`. Для восстановления импортирует его через команду `Copy save game` на внутренний диск. Если меняется владелец, выполняет повторную привязку к Account ID. См. [руководство Apollo](https://github.com/bucanero/apollo-ps4/blob/main/docs/usage.md).
- Apollo монтирует контейнер сохранения, работает с файлами внутри него и затем размонтирует. Создание нового сохранения также затрагивает базу сохранений PS4. Это видно в [исходном коде Apollo](https://github.com/bucanero/apollo-ps4/blob/main/source/saves.c).
- В интерфейсе Itemzflow отдельно названы резервное копирование сохранений игры и импорт с повторной привязкой расшифрованного сохранения. См. [строки интерфейса проекта](https://github.com/LightningMods/Itemzflow-Languages/blob/main/17/lang.ini).

Следствие для PackageFlow: проводник может показать файлы контейнера, но простое скачивание и обратная запись каталога `/user/home/.../savedata` не являются проверенным способом восстановления. Нужна отдельная операция работы с сохранениями.

## Порядок реализации

1. Только чтение: перечислить локальных пользователей и их сохранения, показать игру, Title ID, имя слота и размер контейнера. Не менять базу сохранений и файлы игры. **Готово в WEB:** на PS4 подтверждены два профиля, сохранения 35 и 9 игр и список слотов выбранной игры. Время изменения текущий файловый API возвращает как 0, поэтому интерфейс его пока не показывает.
2. Экспорт: смонтировать выбранный слот в режиме чтения, скопировать его содержимое и необходимые метаданные в отдельный ZIP, размонтировать даже при ошибке. WEB проверяет SHA-256 каждого файла, хранит копию в `.data/save-backups` и даёт скачать ZIP. **Проверено на реальной PS4:** служба 1.36 экспортировала три слота Little Nightmares; WEB проверил все файлы и ZIP. Временные расшифрованные выгрузки на PS4 удалены после переноса. Лимит первой реализации — 64 МБ на слот. Для дополнительной страховки перед восстановлением сохранены исходные зашифрованные контейнеры всех трёх слотов; это аварийная копия, а не основной формат импорта.
3. Восстановление на ту же PS4 и того же пользователя: WEB проверяет ZIP, сравнивает `keystone` и состав игровых файлов с текущим слотом, создаёт новую страховочную копию, отправляет игровые файлы в отдельную промежуточную папку и сверяет их после передачи. Служба сохраняет исходный зашифрованный контейнер, монтирует существующий слот для записи, заменяет только игровые файлы и размонтирует. WEB повторно экспортирует слот и сравнивает SHA-256. **Проверено на Little Nightmares в службе 1.37:** после исправления запись тех же байтов в SaveSlot1 сохранила в игре пункт «Продолжить»; затем отличавшийся SaveSlot1meta из более ранней копии был записан и игра снова показала «Продолжить» и загрузила сейв. В 1.36 замена файла через `rename` приводила к исчезновению этого пункта; возврат точного зашифрованного контейнера восстановил его. После восстановления WEB хранит запись о временном откате, пока пользователь не подтвердит загрузку сейва в игре либо не вернёт прежнее состояние.
4. Перенос на другого пользователя или другую консоль — отдельный этап после проверки привязки к Account ID, `param.sfo` и `keystone` на тестовом сохранении. Не обещать его в первом выпуске. Служба 1.38 добавляет диагностический импорт **зашифрованного снимка этой же консоли**: WEB помещает его в `/data`, служба монтирует снимок только для чтения и выгружает расшифрованные файлы, не подменяя активное сохранение. Тест Unravel TWO показал, что игра прочитала перенесённые игровые данные под новым профилем, но сам найденный архив содержал только начало первой локации, а ожидаемый пользователем прогресс был намного дальше. Нужна другая исходная копия; перенос на другую консоль не проверен.

После любого восстановления нужно запустить игру и проверить, что она читает сейв. Успешный HTTP-ответ и совпавшая контрольная сумма сами по себе этого не доказывают.

## Именные наборы

В разделе «Сохранения» можно назвать набор, например `PS HOME`, и скопировать все найденные профили, игры и слоты. Каждое повторное создание набора с тем же названием даёт отдельную версию: `.data/save-sets/<название>/<номер>/profiles/<профиль>/<CUSA>/<слот>/`. Набор остаётся на компьютере WEB и доступен после переустановки PS4. ZIP содержит метаданные и проверенные по SHA-256 расшифрованные файлы всех успешно скопированных слотов. При обрыве можно повторить только пропущенные слоты; неполный набор отмечается в интерфейсе. Ранее скачанный ZIP можно загрузить в WEB: он проверяется и появляется как новая версия именного набора, без замены существующих копий. Загруженный набор доступен для той же проверки и выборочного восстановления. Сейчас максимальный размер ZIP для загрузки — 1 ГБ; неподдерживаемые или изменённые файлы отклоняются до публикации набора.

«Копия слота» сохраняет один контейнер. «Копия игры» сохраняет все слоты выбранной игры. Именной набор охватывает все найденные игры и профили PS4. Временные копии, которые нужны только для проверки и отката, не показываются в списке ручных копий.

Перед групповым восстановлением WEB показывает совпадение с установленными играми и профилем назначения. Игра должна создать целевой слот хотя бы один раз. WEB сверяет имя каждого слота, `keystone`, состав игровых файлов и контрольные суммы; системные файлы `sce_sys` целевого профиля сохраняются. Каждая запись получает отдельный проверенный откат, пока пользователь не подтвердит в самой игре, что прогресс загружается. Набор с другого IP PS4 сейчас не допускается: перенос между консолями не проверен. Совпадение IP не доказывает, что физическая консоль прежняя; окончательная защита — проверка ключа каждого слота перед записью.

Такой порядок согласуется с [Apollo Save Tool](https://github.com/bucanero/apollo-ps4/blob/main/docs/usage.md), который отдельно работает с расшифрованными сейвами и повторной привязкой при смене пользователя, и с [PS4 Save Mounter](https://github.com/ChendoChap/Playstation-4-Save-Mounter), который требует закрыть игру и предостерегает от замены `sce_sys`. Наша текущая функция не выполняет универсальный resign для произвольного сейва: если проверка ключа или структуры не проходит, запись останавливается.

После форматирования пользователь установил именно Unravel TWO (`CUSA10416`), запустил её под новым профилем `13edcb6f` и создал свежий слот `sce_sdmemory`. Перед переносом создана проверенная расшифрованная копия `588d8acd-d588-4fd4-9007-64a2a9711ec1` и снимок исходного зашифрованного контейнера `.data/save-snapshots/13edcb6f-CUSA10416-before-transfer-2026-09-30/`. Старый снимок профиля `1cabafc7` сохранён в `.data/save-snapshots/Unravel-TWO-before-reset-CUSA10416.zip`; оба его файла сверены по SHA-256. Служба 1.38 расшифровала его на той же PS4 из временной папки, не трогая живой слот. Файлы выгружены в `.data/save-imports/Unravel-TWO-before-reset-decrypted/`; временная папка PS4 удалена. `sce_sys/keystone` старой и новой выгрузок совпал; изменились `memory.dat` и `param.sfo`. Для испытания подготовлена копия `2e80ec77-4c32-4618-bb39-351d68c99ed7`: старый `memory.dat` вместе с системными файлами нового слота. Восстановление подтвердилось проверкой SHA-256; игра после запуска сохранила поля из старого игрового файла. Затем выяснилось, что старый архив содержит лишь начало первой локации (`shore` 25 против 20 в новом сейве), тогда как пользователь ожидал гораздо более поздний прогресс. Поэтому исходный свежий сейв **возвращён точным откатом зашифрованного контейнера**, WEB подтвердил его контрольные суммы (`d1ac4011-c3f7-43b8-b12e-e3bd08a441cd`). Старый архив и расшифрованная копия сохранены для поиска нужного сохранения; в локальном хранилище второго старого снимка CUSA10416 нет.
